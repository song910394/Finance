# H&S 記帳

以 React、TypeScript 與 Vite 建立的個人記帳工具，包含消費概覽、交易明細、信用卡核對、月度帳務、薪資歷程及個人年假管理。介面使用繁體中文，支援手機導覽與 PWA 靜態資源快取。

## 本機啟動

使用 Node.js 20.19 以上，或 Node.js 22.12 以上。

```sh
npm ci --legacy-peer-deps
npm run dev:isolated
```

開啟 <http://127.0.0.1:5042/Finance/>。這個入口只使用合成資料；雲端 API 在記憶體模擬，CSP 禁止外部連線，不讀取環境檔。停止程序會重設模擬雲端，瀏覽器草稿仍會保留；重新啟動時若版本不同，請依提示選擇版本。

`npm run dev` 是一般開發模式，預設只監聽 `127.0.0.1`，網址為 <http://127.0.0.1:5040/Finance/>。一般模式會讀取並自動同步設定的 Google Apps Script 帳本，請先確認使用的是指定測試帳本。`npm run preview` 也只監聽 `127.0.0.1`。

現有 Recharts 2.13 與 React 19 的 peer dependency 宣告不一致，因此安裝沿用專案的 `--legacy-peer-deps`。SheetJS 使用[官方 CDN 提供的 0.20.3](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)，npm registry 的 `xlsx` 舊版不能取代此安全更新來源。

## 資料與操作流程

1. 啟動時先讀取目前帳本的本機草稿，再載入雲端；初次載入完成前不開放編輯。
2. 編輯後立即保存本機草稿，再依序上傳完整帳本。畫面區分「已存本機」、「同步中」、「已同步」與失敗。
3. 本機與雲端不同或其他分頁更新時，暫停自動上傳，由使用者先備份再選擇版本。「其他本機草稿」可載入、刪除單份或清除已處理備份；正在使用的草稿須先完成版本選擇。刪除只影響備份，版本替換時不重複保留相同內容。
4. 手動切換網址要經下載或上傳流程確認成功；失敗重試保留原方向與目的地。
5. JSON 完整備份包含交易、信用卡設定、月度帳務、入帳來源、薪資歷程、年假年度及休假明細。Excel 僅交換交易明細，匯入先檢核與預覽，重複資料需個別確認。

Excel 單檔上限為 10 MiB（`utils/transactionWorkbook.ts` 統一定義）；超過上限會在讀檔及解析前拒絕。讀檔、解析或資料驗證失敗都不會匯入任何交易，請修正後重新選檔。檔案大小限制不能取代 Excel 套件的安全更新，也無法保證壓縮檔展開後的記憶體用量。

概覽、記帳、信用卡與帳務共用選取月份。帳務與帳單未儲存的輸入，在離頁前會提示。

## 年假管理

桌面從側欄、手機從「更多功能 → 年假管理」開啟。年假年度獨立於財務月份，支援跨曆年期間。預設選擇涵蓋台北今天且起始日最近的期間；沒有時選起始日最近一期。沒有年度時顯示「尚未設定年假」與「—／待設定」，不自動建立額度。

- 新增年度須明確填寫起訖日及總時數；名稱可空白，0 額度必須自行輸入。截止日包含當日。已結束期間僅供歷史紀錄，不自動清零、結轉或折現，不代表餘額仍可使用。
- 新增休假選擇「家庭／協會」用途，兩者共用年度額度；舊紀錄未填用途時顯示「未分類」，不從備註推測。登記單日日期、時數、已休畢與選填備註。新紀錄預設未休，同日可多筆；日期與時數相同時需確認可能重複。已過日期不自動勾選，未來不可標記已休；修改已休紀錄為未來日期須自行取消勾選。
- 「新增保留」只填用途、時數與備註，不填日期。保留可編輯、刪除或分次「排定日期」；例如保留 24 小時，排定 8 小時後仍保留 16 小時。一次保存排定紀錄及餘數，避免重複扣除；全數排定沿用原 ID，部分排定建立新 ID。排定後的明細可獨立編輯、刪除，刪除會釋出時數，不自動恢復成保留。
- 總額 T、已休 U、已排未休 P、保留 R 均只計所選年度。剩餘時數為 T − U（尚未扣除已排未休及保留）；可再安排為 T − U − P − R。勾選只在 U 與 P 間移動，排定只在 R 與 P 間移動，皆不改變可再安排時數。
- 桌面已休在左、未休在右；未休包含已排日期與保留區。窄螢幕改為上下排列、未休優先。已休按日期由近到遠、已排未休由早到晚。用途占比只以已休畢時數為分母，包含未分類；尚無已休資料時不顯示假比例。動畫遵循系統「減少動態效果」。
- 以小時顯示，輸入最多小數 2 位，不代表公司的請假單位。集中轉為整數百分之一小時計算，不四捨五入、不推算天數。單一額度、單筆休假及同年度已登記合計的技術上限為 9,999,999,999.99 小時。超額可確認後保存，顯示真實負值。
- 變更年度起訖日若排除既有休假會列明衝突並阻止儲存，不搬移或刪除紀錄。本版沒有年度一鍵刪除。彈出表單開啟時背景頁面與年度選擇暫停操作，先儲存或關閉再切換；未儲存時，取消、關閉、Esc 及離開網站均保留放棄變更提醒。

用途與保留時數沿用 `leaveRecords` 集合：`kind: 'reserved'` 不含日期且 `completed: false`；一般休假為 `kind: 'dated'`。舊紀錄缺少 kind／purpose 仍可載入，分別解讀為已填日期的休假／未分類，不改寫原值。完整備份、重設及版本取代均涵蓋用途與保留時數。

年假與財務資料使用同一個完整帳本保存流程，包含本機草稿、JSON、雲端 payload、衝突及復原備份；不參與金額計算，也不加入 Excel 交易匯出。舊版備份可載入但不合併：匯入確認會明說缺少年假欄位與清空影響；確認前不更動目前資料。完整還原、重設及版本取代均會先保留完整原版本至「其他本機草稿」，備份失敗即停止。格式錯誤、重複 ID、無效日期或孤兒休假會整份拒絕，不部分匯入。

**真實 GAS 相容性待確認：** repository 不含後端。前端及本機 mock 已具備完整 JSON 保存流程，但 POST 成功或 `success:true` 不足以證明真實後端保留新欄位。上線前需在獲授權的測試環境確認後端是否保存完整 JSON，或擴充欄位白名單，並驗證 save → load 及跨裝置結果；本機測試不代表完成真實雲端驗收。

## 已確認的帳務規則

- 每筆信用卡交易只歸屬使用者當下指定的「卡別＋帳單月份」，以 `statementMonth` 記錄。
- 依使用者確認規則，115 年 7 月（2026-07，含）以前未指定帳單月份的信用卡消費，依消費月份歸月並標記已核對；原核銷時間、金額與既有帳單月份保留。8 月與後續月份維持人工核對。
- 歷史整理在帳本載入完成且沒有衝突時執行，先保留完整原版本至「其他本機草稿」，保存失敗即停止；整理標記隨完整備份與帳本保存，避免後續人工更正被再次覆蓋。
- 結帳日用來整理待核候選；候選包含以前未核項目，實際歸屬仍依銀行帳單人工確認。「已核對」不代表已繳費。
- 核銷在待核與已核集合間移動，不改變相同候選範圍的帳單差額基準。帳單金額與人工核結狀態分開保存。
- 編輯已核銷交易的金額、日期、卡別或支付方式前，要明確同意取消核銷。只改用途等文字則保留核銷資料。
- 新分期保存群組、期數及實際每期金額。舊系統預建各期紀錄依名稱末尾的 `(N/M)`、`（分期N/M）` 或 `分期N/M`，搭配卡別、付款方式、分類、總期數及起始月份建立顯示群組，不修改原紀錄。重複或矛盾期數保留待確認。
- 分期沿用「已核對＝已繳款」；預建未核對紀錄不算已繳。剩餘金額加總實際待繳明細，缺期時標示缺漏，不以最新一期金額乘期數補值。
- 月度帳務沿用「期初餘額＋入帳－貸款－手動信用卡費」計算；不再另扣同一批交易。卡費可部分或全部留白後儲存，只保存及計入已填卡費，留白不補零；期初餘額、入帳與貸款仍需填寫。尚未建立的月份顯示未建立。
- 停用入帳來源保留歷史帳務。薪資扣項需要明確填寫，零元成長基準顯示無法比較。

## 程式入口

| 路徑 | 責任 |
| --- | --- |
| `App.tsx` | 導覽、共用月份、帳本更新與保存狀態 |

| `utils/backup.ts` | 完整備份格式與輸入驗證 |

| `utils/billing.ts` | 帳單週期、歸月與差額 |
| `utils/transactionImport.ts` | Excel 交易解析、檢核與重複判斷 |
| `public/sw.js` | 限定同源靜態資源的離線快取 |

頁面與 Excel 套件按需載入。Tailwind 在建置時產生 CSS，不依賴執行時 CDN 或遠端字型。

## 驗證與交付

```sh
npm run typecheck
npm test
npm run build
```

測試使用假的 storage、load/save 與合成資料，涵蓋日期邊界、核銷歸月、分期、月度帳務、匯入驗證、備份、同步重試與分頁衝突。測試不應呼叫真實雲端帳本。

年假回歸位於 `utils/leave.test.ts`、`utils/leaveReservations.test.ts` 與 `services/leaveSync.test.ts`，包含計算基準、時數精度、日期／ID／關聯、用途占比、保留分拆與原子保存、舊新備份、保存重試、分頁衝突與帳本隔離。畫面回歸先啟動 `npm run dev:isolated`，再執行 `node scripts/verify-leave-ui.cjs`。腳本需要環境已有 Playwright 與 Chromium（不新增專案依賴），可用第一、第二參數指定現有 Playwright 模組路徑及 Chrome 執行檔；Windows 受限環境可加 `node --preserve-symlinks`。腳本只允許本機隔離端點，以獨立瀏覽器 context 與合成帳本固定台北今天為 2026-09-22，輸出結果與 1920／1440／1366／1024／768／375／320 px 截圖、80 筆長清單與 125% 縮放檢查至 `.finance-review.local/leave-<時間>/`。

GitHub Actions 在 build 前執行型別檢查與測試。產物路徑為 `dist`，網站 base 為 `/Finance/`。push、Actions、Pages 部署與正式環境資料驗收各自確認，不由本機測試推定已上線。

Google Apps Script 後端不在此 repository。本機驗證不能證明後端權限、備份政策或跨裝置同時寫入的版本鎖定；這些需取得後端來源後另行確認。

GAS 網址是端點識別資訊，不能當作身分驗證。確認雲端授權至少需要後端 `doGet`／`doPost`、身分與帳本授權邏輯、部署存取範圍及執行身分；不可將秘密放進前端程式或 `VITE_*`。本機帳本、草稿與復原資料以明文 JSON 存在 localStorage，同源程式與可存取瀏覽器設定檔的人員仍可能讀取；現有 key、格式與復原機制維持不變。

### 奶霜馬卡龍版面

信用卡設定以並排卡片顯示。刪除前會確認影響筆數並保存完整本機備份；該卡所有交易（含預建未來期次）改為現金、移除帳單月份與卡片設定，保留金額、日期及分期繳款註記。人工填寫的歷史每月帳務卡費保持原值。

共用配色位於 `index.css`：奶油底色、薰衣草紫、薄荷綠、蜜桃粉、奶油黃、天空藍與玫瑰粉。卡片使用淡底與深色文字，輸入框保留白底；錯誤與警示維持語意色。銀行卡依銀行名稱固定配色；分期卡依顯示順序輪替六種色系，搭配小圖案與高對比圓角進度條，同銀行的不同分期也能區分，資訊仍以文字及數字辨識。

1200px 以上概覽將消費分類與帳單概況左右排列、分期最多三欄；帳務摘要與期初餘額同列。平板及手機依原欄數自動重排，資料超出畫面時自然捲動，不裁切內容或壓縮字級以強制塞進一頁。
